# Viability Report

## Position
The current project is viable as an academic proof-of-concept, demonstration and potential foundation for a general-purpose resource-planning tool. Product-market fit, enterprise procurement, defence adoption and financial viability have not been demonstrated.

## Potential user groups
- Engineering and logistics education programmes.
- Student research teams testing constrained planning methods.
- Civilian facilities or inventory teams with relatively low-risk scheduling needs.
- Research partners evaluating transparent data-quality and planning workflows.

The app must not be marketed as a validated defence operations system.

## Differentiation hypothesis
The demonstrable differentiator is evidence-to-decision traceability: explicit synthetic-data labels, independent hard-constraint checks, controlled disruption replay, honest unknown states and JSON evidence export. This is a hypothesis to test with users, not a claim of unique global novelty.

## Adoption barriers
- Users need repeatable improvements against an existing workflow.
- Data owners must permit integration and sharing.
- Security, privacy, access control, support and reliability need engineering beyond this browser-local version.
- A rule-based helper may be insufficient for complex user questions.
- A heuristic may not scale to larger combinatorial problems.

## Validation plan
1. Interview prospective education/civilian users.
2. Pick one workflow and define baseline time, quality and risk measures.
3. Run a supervised pilot using approved data.
4. Compare the same scenarios against a documented baseline.
5. Record user feedback, support effort, errors, unit cost and repeat use.
6. Continue only when benefits exceed build, hosting, security and support costs.

No customer demand, procurement outcome or revenue is claimed in this report.
